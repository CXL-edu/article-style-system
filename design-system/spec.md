# 双色对比排版系统（Dual-Color Contrast Type System）— Spec v2

> 平台无关的内容排版规范，从「轻风格 v2」（2026-08-16 定稿）泛化而来。
> 适用于任何「A 侧 vs B 侧」对比型内容：产品对比、方案对比、观点辩论、新旧对比。
> 哲学一句话：**全文只允许两种语义色，其余全部素净**。颜色是语义，不是装饰。
> `wechat-light-v2`（蓝橙双色）是本规范的默认配色实例；任何平台均可换主题复用。

---

## 1. 设计哲学（不可妥协的三条）

1. **颜色 = 语义**：只有两种语义色（A 侧 / B 侧），颜色只用于标注「这属于哪一方」。花里胡哨 = 多色相同时出现，是设计失误。
2. **两处上色点**：术语着色、金句强调，仅此两处。其余元素（粗体、引用、表格、代码块）全部灰阶/中性。
3. **引用框内不上色**：引用是「复述他人观点」，进入引用框后术语/金句一律降级为纯文本/深色粗体，保持克制。

## 2. 配色规范

| 角色 | 默认值（`wechat-light-v2` 实例：蓝橙） | 说明 |
|---|---|---|
| **A 侧色** | `#2F6BB8` 蓝 | A 方术语、A 侧强调 |
| **B 侧色** | `#D97706` 橙 | B 方术语、B 侧强调 |
| neutral | `#111827` | 金句/粗体（引用框内） |
| text | `#2D3748` | 正文 |
| text2 | `#718096` | 图注、次要说明 |
| border | `#E5E9F0` | 卡片描边 |
| accent | `#6C9EE8` | 表头、引用边条、h2 左条 |
| quote_bg | `#F0F5FC` | 引用底色 |
| code_inline_bg | `#F0F5FC` | 行内代码底 |
| link | `#3B7DD8` | 超链接 |

**衍生规则**：
- h1 下划线 / 分隔线渐变 = `linear-gradient(90deg, A色, B色)`（两色相遇，象征对比）
- 行内代码浅蓝底、链接蓝、引用浅蓝底+蓝边条 = **蓝色系变体**（中性，可保留）
- 代码块语法高亮（绿/橙/蓝/浅绿）= Mac 编辑器惯例，不属于正文配色，保留

**换主题时**：只改 A/B 两色 + 相应变体，其余灰阶不动。示例：华为 vs 苹果 = 红/灰；OpenAI vs Anthropic = 绿/紫。完整调色板与术语映射见 `tokens/wechat-light-v2.json`，组件级视觉基线见 `components/`。

## 3. 标记语言（Markdown 扩展约定）

| 标记 | 含义 | 渲染结果 |
|---|---|---|
| `{{术语}}` | 术语着色 | A 侧色或 B 侧色 + 600 字重（按术语映射表） |
| `==金句==` | 金句强调 | 正文：A 色加粗；引用框内：neutral 深色加粗 |
| `**粗体**` | 普通强调 | neutral 深色加粗（**不加彩**，颜色只留给术语） |
| `` `代码` `` | 行内代码 | 浅蓝底 + 圆角 |
| `[文字](url)` | 超链接 | 蓝色下划线 |

**术语映射表**（config JSON）：`{"A": ["术语1", "术语2"], "B": ["术语3"]}`，未知术语默认 A 侧。

**digest 提取**：剥标记（`**`、`==`、`{{}}`）后截取，用于各平台摘要字段。

## 4. 结构规则

1. **跳过正文第一个 h1**：平台标题栏已展示标题，正文再渲染 = 顶部重复。标题从 md 第一行 `# ` 提取到 title 字段，不进正文。
2. **摘要段在上、引用框在下**：文章头部顺序固定为 摘要段 → 引用框。
3. **引用框内不重复封面已有标签**：封面有「XX版」pill 时，引用里去掉同义前缀，只说内容。
4. **正文开头不放外部重复的标记/标签**。

## 5. 渲染器契约

输入：标准 Markdown + YAML frontmatter（title/author/digest 只用于发布配置，剥离不渲染）
输出：纯 inline-style HTML（无 class、无外部 CSS）——平台粘贴友好（公众号/网页/长图渲染均适用）

```
python3 render_html.py <input.md> [--out <output.html>] [--config <palette.json>]
```

- 默认配置 = `wechat-light-v2`（蓝橙双色实例，源自公众号轻风格 v2），零配置开箱即用
- `--config` 传入调色板 + 术语映射，换主题不改代码

## 6. 平台无关性与适配边界

**设计系统层只定义「内容怎么排」，不定义「发到哪」。**

平台差异只发生在「输出端」：渲染器产物是 HTML，各平台按需转长图 / 直贴 / 裁剪（各平台链路见 `adapters/` 适配层）。内容资产层（标记语言 + 规范 + 渲染器）完全复用。

| 输出形态 | 适用场景 | 归属层 |
|---|---|---|
| 原生 HTML | 支持富文本粘贴的平台 | `adapters/` |
| 长图（PNG） | 图片为主、格式受限的平台 | `engines/html-to-image` |
| 封面 / 信息图（PNG） | 封面、摘要卡、数据图 | `engines/svg-to-image`、`engines/image-pipeline` |

## 7. 迭代纪律

1. 方向性反馈**先对齐再动手**（配色/结构先问清再改）
2. 每轮改动：patch 渲染器 → 本地渲染统计（蓝/橙/金句数量）→ 目标平台验证（DOM 查 span color、h1 数量、图片尺寸）
3. 用户确认后再进下一步；未经明确指令不点「发表/发布」
4. 每次踩坑 → 更新本 spec + 渲染器 + 平台适配手册（沉淀是复利的唯一来源）
